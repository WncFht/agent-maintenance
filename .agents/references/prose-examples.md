# 文字覆盖与清理校准

以下例子是通用化构造，不是产品行为承诺。

| 情况                                                 | 应采用的判断                                                                 |
| ---------------------------------------------------- | ---------------------------------------------------------------------------- |
| 注释“遍历列表并删除项目”，代码已经直接表达           | 删除逐行翻译                                                                 |
| 注释“先停止接收，再等待在途操作完成，最后关闭客户端” | 保留顺序和完成条件，不能压成“关闭时取消任务”                                 |
| “审阅中决定不重试”                                   | 若重试可能重复提交，写明“结果未知时重试可能产生重复提交”，理由必要时归入决策 |
| “根据 decision 7，稍后在下一层 PR 完成”              | 找已提交权威来源；无来源时保留当前确切事实，未完成工作进入明确任务记录       |
| “没有写入，不代表失败前没有副作用”                   | 保留实际失败保证；不要因为否定句而删                                         |
| “兼容旧格式 v2，未知字段按指定规则忽略”              | 真实版本和兼容行为可保留，不能当历史流水删掉                                 |
| “这一版终于修好了问题”                               | 改为当前条件和行为，必要的事故证据放事故记录                                 |
| 为缩短描述，把“可能拒绝”改成“返回”                   | 拒绝，义务与失败语义被改变                                                   |
| 生成目录的 JSDoc 有冗余                              | 修改源注释或模板并重生，不能只改目录                                         |
| 对外 prompt 只做措辞优化                             | 作为行为变更核对调用场景及快照，缺证据时延后                                 |

代码注释应保留非局部结构、复杂局部不变量、竞态、所有权、安全条件与意外失败。测试注释只解释不明显的 fixture、间接观察、平台差异或真实入口选择，不复述断言。

搜索探针可用 PR、decision、reviewer、used to、no longer、上一轮、这一版、审阅要求等词寻找候选；词本身不是违规定义。先用真阳性与近似反例校准，使用 git ls-files 确认范围并补搜隐藏目录，同时排除 vendor 和冻结归档。没有匹配不等于没有残留，继续读范围内最密集的模块注释、README 和决策文字。
