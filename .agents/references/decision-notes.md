# Agent Notes 生命周期与格式

路径为 .agents/notes/{lifecycle}/{class}/YYYY-MM-DD-topic.md。日期为首次提出时间，分类是 feature、bug-fix、simplification、architecture、process、testing。architecture 记录交付代码结构，process 记录周边流程。状态是 proposed、implemented、rejected；archived 单独存放已实施记录。用目录作为清单，不另建中央 INDEX。

首三行为标题、空行和状态：

```text
# Agent Note: 中文主题

Status: proposed
```

正文使用中文章节。proposed 需要“问题、提案、考虑过的替代方案、验收条件、风险”；implemented 需要“问题、决策、考虑过的替代方案、后果”；rejected 保留原提案，“Status: rejected — 原因”承载结论。正文从“问题”开始。完整规则从采用之日起实施，不虚构旧记录的替代方案；旧库豁免需要显式清单及历史证据。

提案实现后改写为现在时事实，删除“提案、计划、迁移计划、验收条件”式章节；验证保留为已具备的证据或明确缺口。事实变化更新原记录，决策反转新建并互链。

新记录搜索相同机制与决策的 active 记录，检查取代。完全取代可合并删除旧记录，前提是当前归属保留所有独有理由、替代方案、后果、验证与覆盖缺口，且修复全部入链。部分取代保持 active 并互链，不靠 git 历史作为唯一理由副本。

功能移除可合并原新增记录，前提是生产、配置、schema、持久化、迁移、兼容和支持性测试都已不承诺该能力。保留原动机、移除原因、完整移除的替代方案、放弃的能力、重新引入条件和不存在的证据。仅移除一个实现、入口或 UI 属于部分取代。

机械变化和小 UI 记录删除。其他已实施记录仅在决策完整、理由不再指导未来且仍有历史价值时封存。安全、持久化、网络语义、所有权、否定保证和容易重犯的备选错误通常仍有指导价值。proposed 不封存，过时提案改 rejected；rejected 仅在防止合理且容易重犯的错误时保留。年龄、字数、行数和数量不是依据。

封存只移动文件、添加归档日期并修复入链。清单逐项登记哈希；附件明确登记，未登记附件不享有冻结保证。封存后禁止编辑、删除、移动和格式化；默认工具跳过历史出链。正文和哈希一起重写必须由可信基线比较拦截。冻结只覆盖已封存字节，不证明移入记录符合价值判断或与旧文件语义等价，封存 diff 仍需审阅。

## 决策范围与交付

一篇记录围绕一个可说明理由的选择；接口目录、实验全过程和逐次实施进展不属于决定本身。允许必要的技术章节，不强制短到丢失机制和后果。转为 implemented 时依照[交付流程](document-lifecycle.md)分配内容；保留原验收的证据或未完成状态，不能只改目录和 Status。
