# 文档布局与交付流程

## 接入项目

先读取项目已有入口、源码布局、研究材料与检查命令。把下表职责映射到已有文件，在项目 `docs/AGENTS.md` 写明归属，在 `docs/README.md` 提供按读者问题组织的导航。已有页面能承担职责时沿用，不为统一目录外观搬文件，也不另建一份全量文档注册表。

| 载体              | 内容与更新时机                                                 |
| ----------------- | -------------------------------------------------------------- |
| 根 README         | 用途、最短使用路径与主要入口；推荐入口改变时更新               |
| 架构参考          | 组件职责、依赖、数据流与所有权；结构改变时更新                 |
| 当前参考          | 配置、接口、失败与限制；行为改变时更新                         |
| 操作指南          | 前提、步骤、成功证据与恢复；操作路径改变时更新                 |
| 研究正文或 theory | 假设、推导、方法与文献；认识变化时修正论证                     |
| 实验报告          | 固定条件下的证据与解释；新证据更新所属研究问题                 |
| Agent Note        | 长期选择的理由、备选和代价；遵循[决策规则](decision-notes.md)  |
| 工作目录          | 临时计划、排队、排错与执行进展；不作为当前行为或研究结论的权威 |

没有既有布局时，可从 `docs/architecture.md`、`docs/development.md`、`docs/reference/`、`docs/how-to/` 开始；研究项目按需采用 `docs/research/` 和 `docs/experiments/`。没有内容就不建立空目录。模块契约保留在模块附近，原始证据与运行目录由项目约定。

## 创建与引用

创建前搜索同一读者问题的现有页面。一次运行、新 seed、新会话或当天进展不是新文档的理由。仅在主题、读者任务或维护周期能够独立时新建；否则更新已有拥有者。

普通页面开头按需要说明主题、结果或用途、适用范围，不规定句数。长页提供章节导航；每节先解释它回答的问题，再进入表格和细节。小文件、机器文件和 Note 不强套摘要模板。目录入口只概述直接子项的用途，不复述各篇全文。关键结论在主页面直接可见，详细证据通常一次点击可达。

引用采用“局部结论或用途＋适用条件＋精确链接”。正文可以重述读者必须知道的符号、假设、安全条件和关键结论，完整定义、长推导、配置全集与数据表只由所属页面维护。不能仅加一个链接而保留原有平行全文，也不能把重要限制隐藏在附件。

新建、移动或合并时同时更新导航和入链。先迁入独有有效内容，确认理由、证据、负结果与复现依赖均有去向，再删除被替代正文。历史实验引用当时源码和条件，不跟随当前接口改写观测。

## 从任务到交付

1. 明确期望结果、当前行为及受影响消费者，找到源码、现有文档和决策拥有者。
2. 有长期设计取舍时更新或创建 Note；普通局部修改直接实施。实施计划放任务上下文或工作目录。
3. 实现与验证同时更新当前契约。文档命令按展示方式核验；缺少运行环境时明确未验证范围。
4. 交付前分配内容：设计理由留 Note，当前接口归参考，操作归指南，科学证据归实验报告，完整推导归研究正文，执行流水归工作目录。
5. 提案实施后逐项核对原验收。未满足的要求继续保持未完成；独立后续工作明确归属，不通过拆文档降低验收。
6. 修复导航、文件链接和锚点，检查事实与证据状态，再按[篇幅规则](document-budgets.md)处理超限。格式通过不代表语义或产品行为通过。

新进度应改写所属段落，不在稳定正文末尾不断追加“最新进展”。临时材料确需入库交接时，标明责任人、复查日期和预期归属；工作结束后提取结论并移除已解决的流水。Git 保留编辑历史。

## 阅读验收

从入口能找到当前行为、操作与证据。研究记录能说明问题与证据的联系。读者通过相关入口能理解主题、关键限制和进一步核验路径；不要求先重建会话历史。内容归属由审阅判断，不做重复检测或自动删文。
