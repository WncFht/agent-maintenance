# 编写升级迁移指南

涉及 CLI、配置、持久化用户数据、SDK、网络消息、发布包和入口的破坏性变更识别后立即写。所有内部消费者同改且没有外部承诺的内部 API 不自动写指南。持久化专门记录仍由其所属规则管理，指南只说使用者动作并链接。

先从实际版本权威来源确定相邻发布区间；采用 docs/upgrade-guide/v<起始版本>/<主题>/guide.md，目标已有约定优先。当前未发布区间随同一行为更新，破坏被撤销则删除指南；已发布区间冻结，不一篇横跨多次发布。

从[中文模板](../templates/upgrade-guide.md)开始。仅“变更”和“迁移”：受影响人群、原新行为、按序修改的文件/键/命令/符号、成功验证与必要风险。写可执行短路径；解释与理由归 notes，重复机械步骤优先已有迁移命令。

上游英文 500 词是短指南目标，中文不机械换算；需要很长时先检查是否重复代码或混入设计。运行实际迁移及文档检查，不能凭记忆写自动恢复和回滚保证。
