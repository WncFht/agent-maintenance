# 按研究问题维护实验

## 一个问题，一个主报告

Study 表示研究问题，protocol 表示比较协议，run 表示一次实际执行。多组设置、seed 和重试进入配置与证据，不各自生成长期报告。新模型或协议实质改变时明确分组；无法共同回答原问题时才另立主题。

沿用已有报告路径；新主题可使用 `docs/experiments/<topic>/README.md`，独立支撑材料放同目录 `support/`。小主题不建附件目录。主导航列问题，问题报告链接支撑材料；支撑材料回链所属问题。共享方法确实服务多个主题时进入研究或参考拥有者，不复制多份。

## 三层证据

| 层次     | 保留内容                                                     |
| -------- | ------------------------------------------------------------ |
| 主报告   | 回答研究问题所必需的实验、主要结果、反例、限制与综合结论     |
| 支撑报告 | 实现一致性、测量可靠性、详细误差或专项验证；说明支持哪个前提 |
| 原始产物 | 实际配置、源码身份、逐样本输出、日志、统计与图表生成输入     |

按证据对结论的作用分层，不按 CPU/GPU、成本或是否符合预期分层。CPU 反例可能需要进入主报告，GPU 启动 canary 可能只支持工程可用性。关键失败必须在主报告可见。已有测试与结构化产物能充分说明的检查，不再创建 Markdown。

主报告采用[问题报告模板](../templates/experiment-report.md)：共同问题和协议，每组实验依次写“背景、问题与动机”“算法与实验设置”“结果、分析与结论”，最后综合各实验。共同设置只定义一次，各实验保留理解比较所需的关键条件并链接完整配置。[支撑报告](../templates/experiment-support.md)只展开窄问题，不重复项目背景。

## 协议与执行身份

执行前明确命题、反驳条件、基线、主要指标、统计单位、比较预算、停止条件和结果选择方法。探索中调整协议时留下版本与理由，不把看过结果后的选择描述为事先确定。此流程不授权扩大 GPU、时间或费用预算。

每个可引用 run 记录实际执行源码与未提交差异、解析配置、模型/tokenizer/数据身份、样本集合、采样与终止规则、目标与估计器、停止梯度与更新顺序、精度、依赖、seed、实际预算和退出原因。由现有运行工具保存，不在多篇文档手抄完整清单。只有 commit 或目录名不构成未提交源码的身份。

区分运行完成、证据核验通过和假设得到支持。训练结束但评测缺题属于证据不完整；不支持假设的完整结果仍是有效证据。核验样本覆盖、重复/遗漏、协议一致性和指标复算，记录排除原因。多次回答采样不替代独立训练 seed；同更新步数不自动等于同 token 或计算成本。

## 更新与保留

新增 seed 更新原实验；新的消融问题增加实验小节；新证据修正结论时说明依据，保留原始观测与必要负结果。结果写观察，分析写解释及其他可能性，结论只陈述证据允许的判断。CPU 恒等式、工程 canary、完整训练和正式 benchmark 不互相代替。

实际设置以 run 的解析配置为准，报告解释比较设计。结果表和图从保存的数据生成，记录分析代码及输入身份；重评分或协议变化产生可区分的分析结果，不覆盖原始证据。后续诊断需要 checkpoint 时提前规划；未保存权重就明确相应后验分析不可用。

支撑报告被引用时，主报告保留“结论＋适用范围＋链接”。证据适用的源码、协议与分析身份必须可追溯；当前实现变化不使历史测量自动失效，也不使其自动成为当前实现的验证。

原始证据保存在项目约定的稳定位置；`runs/` 被 Git 忽略不等于可随时删除。清理临时运行前确认报告依赖的配置、源码身份、输出与必要日志已持久保存。排队、PID、安装和逐轮重试只进工作记录，不追加到科学论证中。
