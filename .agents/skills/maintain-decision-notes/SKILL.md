# 维护决策记录

读取[记录规则](../../references/decision-notes.md)和目标 note。新建前搜索 active 生命周期目录，确定是否已有同一决定，逐项判断完全或部分取代；不要为了数量新建重复文件。

仅为代码、测试与已有文档不能充分表达的长期理由创建。提案、已实施和拒绝使用不同结构；替代方案必须真实存在。状态改变时改写正文，不能仅改目录和 Status。

保留能指导未来的所有权、安全、持久化、wire 语义、否定保证、替代方案和重新引入条件。小补丁、性能修改或局部能力也可能有长期价值，不能按实现大小判断。机械与小 UI 流水删除。

完全取代可合并，但归属记录须保留独有理由、后果、验证及覆盖缺口并修复入链；部分取代保持两份互链。实际功能仍有数据或兼容承诺时不算完整移除。

只有已实施、理由不再指导未来而仍有历史价值的记录才封存。proposed 过时改 rejected，rejected 仅在阻止容易重犯的错误时保留。不使用年龄、字数和清理配额。

封存仅移动已核实的文件、添加归档日期、修复入链并追加哈希；检查附件登记与可信基线保护，遵循[归档指令](../../notes/archived/AGENTS.md)。工具不能判断价值或证明移动前后内容等价，仍需审阅完整封存 diff。新记录只触发相关主题审查，不扩大成全仓治理。
