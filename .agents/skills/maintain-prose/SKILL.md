# 维护文字与注释

先明确范围和任务授权。审阅、审计只报告，实施任务才改写；没有范围时先确定对象，不默认全仓扫描。排除第三方源码和冻结归档。生成目录、快照与 fixture 属于派生物；追踪所有消费者，修改来源后同步。

编辑前列出命题：主体与动作；条件、时间、顺序；必须或允许等义务；否定保证与例外；所有权、副作用、失败和后果。每项有效事实都须保留。字数更少不是独立改进指标。

调用点保留完整本地契约；架构、长推导和历史理由链接其归属。遗漏会诱发误用或错误简化的理由应保留。补齐与恢复和删除同样重要，不能只做缩短。

公共接口写返回区别、异常、副作用、归属、取消及持久性；内部注释解释非局部结构、复杂不变量、竞态与意外失败；测试只解释不明显的设计。README 写消费者行为、配置、失败、限制和扩展；决策记录保留理由、备选、验证和缺口。诊断写失败对象、违反的规则与可行动修正。

模型或用户可见字符串是行为。核对来源场景、可访问性名称及快照，不把它混入无验证的纯文字清理；授权范围内缺少所属场景时延后并报告。

按 keep、add、trim、restore、restructure、defer 判断每项，参考[校准案例](../../references/prose-examples.md)。会话编号、审阅辩解和实施后计划按[会话残留审计](../../references/reasoning-residue.md)处理。如果两个版本都保留事实但存在真实取舍，可报告或按用户要求校准；不制造劣质备选。确认原则后应用到范围内同类内容，例子保留原则而非审阅流水。
