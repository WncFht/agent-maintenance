# Agent Note: Crossnote 主题、渲染与部署边界

Status: implemented

## 问题

正文已使用纸张语义变量，Mermaid 却保留宿主默认色或被整图滤镜压暗。为主题切换再增加渲染器，会引入源码缓存、并发初始化和打印时序。原有软链／硬链混合部署还依赖 inode，原子保存后可能只更新一部分工作区资源。

## 决策

Mermaid 继续由宿主负责结构和布局，本地通过限定图种的 `themeCSS` 消费文档变量。颜色变化不调用渲染器；几何、字体度量和原生图内配置仍属于 Mermaid。适配先覆盖五类图，数据图保留原生色；`.native` 明确退出文档配色，避免同时承诺作者色板和页面色板都完全主导同一图。

纸张、标签和字体从 `src/theme.json` 生成。维护源码与宿主固定入口分离，伪代码纯逻辑从一个文件生成 QuickJS 和浏览器目标。构建给正文 CSS 添加组件边界，并为宿主再次执行 LESS 包装声明值；否则已编译的新 CSS 颜色语法可能被旧宿主解析器误解。

浏览器增强采用 MPE 0.8.40／Crossnote 0.9.42 的受信任本地 head 脚本入口，只需要用户级预览脚本许可和工作区信任。`@import` 资源列表仍受代码块执行开关影响，因此解析器不再为增强脚本改写 Markdown，也不要求开启执行任意代码块。轻量入口在宿主替换初始 DOM 后恢复外观控件，图表操作与伪代码回退按实际内容延迟加载。

独立保存从已有 SVG 固化样式、尺寸和可嵌入资源，不使用另一个 Mermaid 版本重新排版。HTML 标签和网页字体由浏览器计算后的结果保存；不可读取资源显式失败。系统字体仍依赖接收环境，打印与其他 SVG 消费者的能力边界分别说明。

图表查看器复用快照准备，触控板输入、视口与选择的独立约束见[图表视口交互](2026-10-25-Crossnote图表视口交互.md)。查看器的克隆不改变原图的主题与导出归属。

部署改为显式同步受管副本，以构建哈希和上次部署清单识别漂移／定制。全部冲突预检后才写入，清单最后更新，普通失败回滚；强制终止和回滚失败保留恢复材料。维护源不被目标写穿，不维护全局项目注册表，也不自动修改全局预览配置。

本记录部分取代[工具链接入](../process/2026-10-17-工具链接入与暂存格式化.md)中的 MPE 链接部署选择；其 hook 和通用工具链决定保持有效。

## 考虑过的替代方案

- 主题变化后重新初始化 Mermaid，需要额外处理队列、缓存失效、过期结果和打印准备；CSS 已能满足当前需求。
- 接管渲染并使用 Shadow DOM 隔离更强，但会增加宿主生命周期与导出适配。当前拥有正文样式源码，可以直接划定组件边界。
- 全部转为 img 会切断页面变量，也限制图内文本与交互；图像用于独立导出，不作默认显示模型。
- 替换 beautiful-mermaid 会引入另一套语法覆盖与布局行为。新风格包、全局 ELK 和通用插件框架没有当前必要性。
- 延续链接部署能立即传播修改，但不能可靠表达部署身份；显式同步以操作成本换取可诊断和独立的工作区资源。

## 后果

新增图种需要补适配规则和行为样例，不新增主题控制器。Mermaid 内部 DOM 升级仍需要回归，未知图种不能被自动宣称支持。源码修改要构建并显式同步；本地定制不会被强行覆盖。旧部署按[迁移指南](../../../../docs/upgrade-guide/unreleased/crossnote/guide.md)升级。

自动化验证覆盖两套 Mermaid、六种纸张、作者配色、几何稳定、HTML／SVG 标签保存、资源失败、真实 Crossnote HTML／PDF，以及部署冲突与回滚；入口见[预览验证](../../../../assets/.crossnote/tests/README.md)。MPE webview、其他导出工具和接收端字体分别验收，不能由相邻路径的成功替代。
