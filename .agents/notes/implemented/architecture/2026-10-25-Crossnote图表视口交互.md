# Agent Note: Crossnote 触控板与图表视口

Status: implemented

## 问题

按 wheel 事件数量固定跳倍率会让触控板缩放依赖事件频率，修改图片尺寸还会改变焦点位置。MPE 0.8.40 在 document 捕获阶段接管 Ctrl／Meta-wheel，内部查看器监听无法收到 Chromium 的合成 Ctrl 捏合事件。增加节点选择后，点击、拖动和图形身份也需要统一处理。

## 决策

以触控板体验为优先约束：双指滑动始终平移，捏合连续缩放，不自动猜设备切换行为。Chromium 捏合按其源码约定 `exp(-deltaY / 100)` 还原幅度；输入逐条更新相机，每帧合并 DOM 写入。导航不重新布局 Mermaid，不叠加人工惯性和缓动。

查看器打开期间在 window 捕获阶段接管属于当前画布的 wheel，先于 MPE 的 document 处理，直接更新相机并停止传播。小地图复用相同输入与相机；倍率菜单内拦截修饰键滚轮，避免误改文档倍率，其余区域保留宿主处理。关闭或被移除后释放监听。原生 momentum 可用时保留惯性归属；缺少时只对最近平移中的物理修饰键做保守降级，不能因此推迟合成 Ctrl 捏合。

视口只有一份位置、倍率和 fit／manual 状态。外层 transform 控制图形，fit 随尺寸变化重新适配，manual 保留图中中心；原有的图形边界限制由[自由画布决策](2026-10-25-Crossnote自由画布与查看器隔离.md)取代。尺寸保留小数精度，事件坐标转换考虑宿主 CSS zoom，不将设备像素比当作图形倍率。

小地图按需复用快照，缩略范围包含图片与可见区域；拖动时固定映射，避免范围变化改变抓取位置。它不维护第二份相机状态。

查看器采用已有快照流程生成的 SVG 克隆，重命名 ID 与局部引用，去除作者交互和动画。受支持图种的节点提供命中、标签和键盘焦点；单选外框独立于图形，拖动阈值按屏幕 CSS 像素判断。着色支持与可选节点支持分别验收。实现与当前操作归 [Crossnote README](../../../../assets/.crossnote/README.md)，主题与导出边界沿用[原决策](2026-10-25-Crossnote主题与部署.md)。

## 考虑过的替代方案

- 修复原生滚动容器可以保留浏览器的滚动机制，但缩放焦点、跨居中边界和节点外框需要协调尺寸与滚动位置。当前选择 transform 是为了共享导航和选择坐标，不宣称它在所有图形上都更快。
- d3-zoom 或 Panzoom 可以承担部分视口计算，但仍需处理宿主事件归属和触控板幅度。现有需求不需要为了这部分引入通用运行时。
- use-gesture 或 wheel-gestures 在 Safari 手势、复杂惯性降级成为实际需求时值得重评；当前不增加完整跨浏览器手势承诺。
- 自动识别鼠标并改成滚轮缩放会让同一动作的含义变化，违背触控板优先要求。额外的鼠标模式、编辑器 SDK、旋转与多选不进入当前模型。

## 后果

宿主如果把拦截入口移到 window 捕获阶段，需要重新验证监听顺序。原生 momentum 的存在不能证明所有硬件均正确提供惯性信号，旧内核的物理修饰键降级也不能准确识别所有手势结束。Safari 独有 GestureEvent、触摸屏多指和真实 Mac 输入需独立验收。

自动化覆盖连续输入与事件拆包、宿主捕获模型、缩放焦点、尺寸变化、ID 引用、真实 Mermaid 11／12 标签、选择与拖动分离，以及关闭／移除／失焦清理，入口见[验证说明](../../../../assets/.crossnote/tests/README.md)。浏览器合成事件不是 Mac 硬件或高刷新率性能证据。新增节点适配须保留原图与导出不变，新增手势须保持触控板的现有操作含义。
