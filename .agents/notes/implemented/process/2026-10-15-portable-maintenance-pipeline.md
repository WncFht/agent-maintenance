# Agent Note: 通用维护包的职责与验证边界

Status: implemented

## 问题

从产品仓库提取的技能和脚本不能直接证明其他项目的行为。原提取包混合了任务入口、专项方法与产品工作方式，保留过多技能也会增加选择和引用维护成本。

## 决策

原决定采用维护文档、维护文字、维护决策记录、审阅变更和选择验证五个技能，并把专项方法作为按需参考。技能集合和源码、基准目录安排已由[文档维护范围决定](2026-10-15-documentation-only-scope.md)部分取代；下述暂存快照与归档保护决定继续有效。产品 UI、图标、演示和堆叠 PR 流程不在活跃集合中。

提交 hook 检查 index 导出的快照；推送和 CI 复用配置驱动的检查入口。PR 另用目标分支版本的检查器和事件提供的 base SHA 检查冻结历史，避免待审内容同时改写记录、哈希与检查器。远端工作流和合并保护本身仍需托管平台权限控制。

## 考虑过的替代方案

保留完整技能集合能减少重组，但会把产品流程当成通用入口。只保留工作区检查实现较短，却不能识别“修复未暂存”的提交。只对照当前归档清单不能拦住正文和哈希一起修改。

## 后果

本地增加开发依赖安装和暂存快照检查成本。文档检查覆盖本地文件链接与技能结构，不证明外部链接、锚点、示例行为或规则质量；Notes 检查不判断决策价值。托管 CI 未运行前，仅报告本地验证结果。

markdownlint-cli2 更新到 0.23.3，KaTeX 与 TOML 解析器使用修补版本；npm audit 仍报告由 braces 3.0.3 传递造成的五个 high 条目，查询时 braces 没有更新版本。它用于开发工具的仓库 glob，不接收产品用户输入；保留该工具并等待上游修复，不能报告依赖审计为零风险。
