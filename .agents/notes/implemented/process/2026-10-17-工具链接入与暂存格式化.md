# Agent Note: 工具链接入与暂存格式化

Status: implemented

## 问题

维护规则与工具链分别维护会增加配置漂移和重复接入成本。仅检查 Markdown 会漏掉代码注释；AutoCorrect 还会误改配置语法与外部标识。pre-commit 隐藏未暂存改动期间由 formatter 改写 index，会破坏补丁恢复条件。

## 决策

维护技能、接入方法、经过测试的语言配置和可选 MPE 资源在本仓共同维护。代码文字默认只检查，Markdown 可自动整理。两阶段 hook 在框架外先运行暂存 formatter，再运行框架检查；真实 Git 测试覆盖部分暂存、未暂存修复和格式冲突。

此决定部分扩展[文档维护范围](2026-10-15-documentation-only-scope.md)，增加工具链接入，不恢复通用产品审阅、验证选择或性能框架。目标项目复用已有检查入口，复制时记录来源版本，不建立对全局 skill 的运行时依赖。

## 考虑过的替代方案

将工具链接入作为独立 skill 维护会产生两套配置来源。统一复制完整调度器会替换目标已有构建入口。把所有代码交给 AutoCorrect 自动修复会改变外部名字、规则和 fixture。把 formatter 放在 pre-commit 隐藏差异期间会导致补丁冲突；实际提交反例已复现。

## 后果

安装入口负责两阶段顺序，不能用普通 pre-commit install 替代。git-format-staged 工作区合并失败时会警告且保留原文，index 可能已改变，需审阅两侧差异。MPE 的两个硬链要求同文件系统，源原子保存后须重建。预览浏览器测试和 VS Code 扩展实际展示分别验证，不互相替代。
