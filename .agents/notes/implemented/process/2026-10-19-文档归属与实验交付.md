# Agent Note: 文档归属与实验交付

Status: implemented

## 问题

文档维护规则说明了表达与决策格式，但新建页面、提案完成后的内容去向和研究证据层次缺少具体流程。仅检查文件链接不能发现已经失效的章节引用；仅提倡短文也没有可执行的常驻入口预算。

## 决策

保留三个技能入口，用共享参考和模板补足目录适配、内容交付、按研究问题维护报告及支撑验证。重要性由证据对结论的作用决定，CPU/GPU 只是执行类型。当前参考、决定理由、研究证据和工作流水各有拥有者，迁移保留独有内容并修复入链。

文档检查加入本地锚点与项目声明的字符预算。硬预算只用于明确列出的常驻入口，软预算只提示。按用户要求不实现重复检测；文本重复和事实归属由审阅判断。此决定补充[文档维护范围](2026-10-15-documentation-only-scope.md)，不恢复通用产品审阅、性能或实验执行框架。

## 考虑过的替代方案

为每个环节增加新技能会增加选择与引用成本；现有文档和决策入口能够承载流程。统一限制全部文档行数无法适应完整证明与实验报告。按 CPU/GPU 分主次会隐藏重要反例。自动查重既不符合采用要求，也不能判断必要的假设重述与多份权威说明之间的区别。

## 后果

项目接入需要明确自己的页面归属、预算与检查范围，不能只复制目录。锚点或预算违规会阻断文档检查，软提示不会改变完成状态。原始证据、冻结历史和未完成验收继续保留其原有约束；科学结论仍需核验实际数据。
